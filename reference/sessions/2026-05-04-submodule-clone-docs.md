# Maintenance Session: Submodule Clone Documentation

**Date:** 2026-05-04
**Status:** Complete

## Intent

Close a small onboarding gap discovered mid-session: people cloning an
NLA project (the framework itself, or any project generated by
`/create-app`) need `--recurse-submodules` (or a follow-up
`git submodule update --init`) to actually fetch the framework
submodule. Both READMEs documented the two-step form but didn't mention
the one-step `--recurse-submodules` alternative. Surface the one-step
clone as the primary instruction; keep the two-step as the
already-cloned fallback.

## Context

The user asked a verification question: "Won't `git clone` fail to
install submodules, and won't they need to be at tagged versions?"
Initial diagnosis identified two gaps: (1) `/create-app` not pinning
to tagged releases, (2) READMEs not mentioning the one-step clone.

On verification, gap (1) didn't exist — `.claude/skills/create-app/SKILL.md`
already has step 1a (lines 240–242) that runs the same tag-pin pattern as
`/install`. The gap was a misread caused by a grep result that elided
"long matching line" without showing its content. Reading the file
directly would have surfaced the existing behavior.

Only gap (2) was real, and the fix was small.

## Changes Made

- **`README.md` lines 78–83** — Primary clone instruction is now
  `git clone --recurse-submodules`. The two-step form
  (`git submodule update --init`) is shown below as the equivalent
  for already-cloned repos.
- **`.claude/skills/create-app/SKILL.md` line 319** — Generated NLA's
  README now suggests `git clone --recurse-submodules [url]` with the
  two-step as fallback. Future `/create-app` runs produce a slightly
  different generated README; existing projects unaffected.

## Decisions Made

- **`--recurse-submodules` as primary, two-step as fallback** —
  Alternatives: keep two-step as primary (status quo), or replace
  two-step entirely. Chose primary-with-fallback because the one-step
  is the more common idiomatic form, but the two-step still matters
  for users who've already cloned without the flag. Both forms
  produce identical results — submodules pin to specific commit SHAs
  in the parent repo, so `--recurse-submodules` checks out exactly
  what's pinned (which, for tagged-release pins, is the
  tagged-release commit).

- **Skip tag and update-note (treat as internal commit)** — Per the
  framework maintain.md taxonomy, `.claude/skills/` is "framework
  maintenance behavior only" and `README.md` is "framework
  documentation only" — neither is in the consumer-facing bucket
  (`core/` or `install/*.md`). Existing domain projects running
  `/update` see nothing new from this commit. Only future
  `/create-app` runs produce a different generated README, which is
  a forward-looking change rather than a change to content existing
  projects depend on.

## What Didn't Work

- **Diagnosing from grep output alone.** The initial claim that
  `/create-app` lacked tag-pinning came from a grep result where the
  matching line was elided. The fix would have been to read the file
  contents directly when the match was about behavior I was about to
  recommend changing. This is exactly the "verify before
  recommending" caveat in the auto-memory instructions — a memory
  (or, here, a grep snippet) that names a specific behavior is a
  claim that it existed; before recommending it, verify.

## Debrief

Two observations worth carrying forward:

1. **Grep elisions are not "no match found."** When grep returns
   "[Omitted long matching line]," that's a positive match the tool
   chose not to display. Treating it as if the match wasn't there led
   to a confidently wrong recommendation. Worth a moment of pause
   when a grep result includes an elision and the match content is
   load-bearing to a recommendation.

2. **Verification questions catch real gaps.** The user's question
   ("won't this break?") surfaced a real (though small) issue. The
   pattern is worth honoring: when someone asks "does X seem right,"
   the answer often involves checking whether X is documented
   correctly, not just whether X is conceptually right.
